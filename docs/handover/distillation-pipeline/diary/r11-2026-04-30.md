## P2 — Strict-filter retrofit (R10 closure note tri-criterion)

R10 closure note (`docs/handover/teacher-viability/diary/r10-2026-04-30.md` §"Closure notes for the distillation wave"):

> Distillation training-data export filter must be `RUN_COMPLETED:passed AND finalState == 1.0 AND step-coverage == 1.0`, NOT just `passed`.

The two failure shapes the strict gate isolates:

1. **Premature** — Pro 3 declares done before satisfying final-state. R10 sweep had 13/20 gemini-react RUN_COMPLETED:failed plus several RUN_COMPLETED:passed cases where `finalState` scored 0.0–0.5. Status-only filter rejects RUN_COMPLETED:failed (correctly) but accepts the partial-finalState-passed cases (incorrectly — those are premature).
2. **Over-execution** — Pro keeps tooling past the success state, often to MAX_TOOL_ROUNDS. Exemplar: `calibration-2-single-nav-news`, where Pro hit all 3 STEP_DONEs then ran 2+ levels deeper. Status-only filter ACCEPTS this case; the trajectory is contaminated downstream.

Status-only filter passes (1) and (2). Tri-criterion conjunction blocks both.

### Sub-decisions (surfaced to lead before writing code)

**Decision 2A — emission seam**: chose `scripts/wave-r5-ab/build-report.ts` over `runners/trace-recorder.ts`.

Rationale: build-report is where score computation lives. `score(task, projection)` at lines 251-288 already calls `stepCoverage(...)`, `finalState(...)`, `furthestKeyNode(...)` for every (runner × task) ndjson, with the EvalTask registry in scope. Trace-recorder doesn't have an EvalTask reference at write time — wiring scoring into the recorder would couple it to the task layer and duplicate the report logic (CLAUDE.md "no duplication"). Build-report's single-pass aggregator IS the canonical scoring layer; sidecar emission slots in next to the existing `rollupsByRunnerByTask` Map population.

Cost: build-report becomes mandatory before distill:export against a new trace archive. Acceptable — the report is canonical for any sweep that gets compared.

**Decision 2B — backfill strategy**: chose retroactive (re-run build-report over R10 archive) over re-eval.

Rationale: re-running the wave-r10-pro-preview sweep wastes ~$25 + 3hr wall-clock; the existing 60 ndjson files already contain everything build-report needs (status_marker payloads, key-node URL extraction, tool-call counting). Retro path is `pnpm wave-r5-ab:report --trace-dir <wave-r10-pro-preview>` once per archive. Same one-shot covers any historical archive (`baseline/`, `post-q9-fix/`, etc.).

Both decisions match the plan's leans (P2 text "lean is build-report" + "lean is retrobackfill"). Lead acknowledged via SendMessage at session-start.

## P3 — Path B grammar-override conformance test

Per Wave 5 diary §"Training-sample format decision" + assessment §9, the existing exporter already emits Path B-shaped output: `assistant.toolCalls[].arguments` is a JSON string carrying the args object, and the production runtime parser at `packages/shared/src/react-envelope.ts` decodes that args object into the strict per-tool `ActionVariantArgs` union.

P3 pins this contract via a regression test. Without it, a future exporter change that mistypes `command`, emits unknown arg keys, or shape-shifts `args` would teach `browsing-gemma` to emit envelopes the production reducer rejects — the third-strike pattern from `feedback_no_test_only_injection_seams.md`.

### Implementation

New test in `packages/evals/tests/teacher-data-exporter.test.ts`: "Path B conformance: every emitted assistant.toolCalls[].arguments round-trips through parseAgentTurn as a strict ACTION envelope".

Synthetic trace fixture covering all three dispatcher tools:
- `interact { action: { command: "navigate", url: "https://example.com" } }`
- `observe { action: { command: "snapshot" } }`
- `trace { action: { command: "start", reload: true, autoStop: true } }`

For each emitted `toolCall`, the test:
1. Parses `arguments` JSON.
2. Synthesizes the wire envelope `{ _tag: "ACTION", stepId: "step-N", toolName: <name>, args: <parsed> }`.
3. Runs through `parseAgentTurn(envelope)` from `@neuve/shared/react-envelope`.
4. Asserts `instanceOf(decoded, ActionTurn)`.

The test exercises all three dispatcher branches (`InteractArgs`, `ObserveArgs`, `TraceArgs`) of the strict per-tool union. If any future emission shape drifts from canonical, the test fails at PR time.

### Verifiable

```
$ pnpm --filter @neuve/evals test -- teacher-data-exporter
... 
Path B conformance: every emitted assistant.toolCalls[].arguments round-trips through parseAgentTurn as a strict ACTION envelope (R11 P3) ✓
```

R10 strict-pass traces (calibration-1, trivial-1) export cleanly under the strict filter from P2 — both have `tool_call.name = "interact"` / `"observe"` (bare names, matching production parser) and well-formed args; the round-trip works.

The pre-existing PLAN_UPDATE round-trip test at `teacher-data-exporter.test.ts:514-624` covers the PLAN_UPDATE leg of the envelope union; P3's new test covers the ACTION leg. Together they pin both wire shapes the model is being trained to emit.

**Effort**: small. Single test addition + 3 imports.
